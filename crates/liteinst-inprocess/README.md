# Caller-owned in-process page gate

This crate eagerly consumes already completed core publication. It makes a
private caller-owned region NX and handles its actual first instruction-fetch
fault in the same process. It has no ptrace or liteinst-launch dependency.

`unsafe PreparedGate::new(&mut owner, address, &final_bytes, &instructions,
&bundles)` borrows both the executable owner and an independent immutable final
snapshot. `unsafe arm()` checks the real main-thread singleton registry and RX
mapping, installs SIGSEGV plus a guarded altstack, and removes execute permission.
The resulting `ArmedGate` is neither Send nor Sync. `metrics()` distinguishes the
first touch from later calls; `disarm()` and Drop restore RX and the exact prior
SIGSEGV, signal mask and altstack before the borrowed owner can be reclaimed.

Each sorted `InstructionExtent { offset, len, bundle }` describes final machine
bytes, including a generated E9 if present. `PageBundle { first_page, page_count }`
is the caller's complete page dependency closure. A crossing instruction needs
both fetch pages. A CALL ending at page end does not need its return page opened.
The unsafe contract supplies complete entries/resumes, immutable source/aliases,
continued singleton ownership, and exclusion during publication/arm/disarm. It
also excludes changes to mappings, signal state, thread topology and runtime
ownership while armed. Forgetting an armed guard does not release those unsafe
lifetime obligations: its registered source/snapshot/owners must remain live.
These are not inferred from an ELF symbol table.

The handler performs no allocation, decoder, formatting, lock or libc call. It
checks native SIGSEGV/SEGV_ACCERR/#PF/fetch provenance, saved head, fault extent,
pending page and every final byte in the dependency bundle. It opens RX via raw
mprotect, executes registered private expedited sync-core and local serialization,
and leaves the complete kernel ucontext untouched. Foreign/nested faults, changed
bytes, uncertain permission restoration and sync failures poison and terminate.

All tables are prepared before NX. Fixed bounds are 16,384 source pages,
262,144 final heads and 16,384 bundles; a guarded 256 KiB altstack is allocated and
checked against the actual kernel signal-frame minimum before activation. These
are this leaf's bounds, not a claim about whole-program memory or B3 capacity.
Core publication/trampoline ownership remains external and must outlive disarm.

The `selected` module uses the genuine core planner and publisher to replace
CPUID, RDTSC and returning read/write/getpid/gettid syscalls. It retains the
actual installed owner, publication receipt and observed source/generated bytes.
Read the [execution contract](CONTRACT.md) before using this unsafe interface.
Unsupported syscall requests terminate before executing that request.

Six pure tests check metadata and refusal behavior. The separate fresh-process
`native_probe` executes ten cases: CPUID, RDTSC, four returning syscalls, raw
EBADF, a crossing instruction, a crossing E9 and a boundary CALL/RET. The nine
state cases compare GPRs, flags, qualified XSTATE and the red zone. The boundary
CALL case observes the actual pushed return address and admission counters.
The fresh-process probe explicitly relinquishes Rust's stack-overflow SIGSEGV
handler while it owns the gate, then restores that disposition after disarm.
Success requires process exit zero after restoration, as well as its JSON row.

Run `python3 evaluation/inprocess/run.py --iterations 1000` from the repository
root with committed source. It builds in release mode and records all 17 timing
batches per case, exact commands, revision and hardware in compact JSON.
Publication is eager; first-touch admission is lazy. First-call timings include
the capture wrapper, and handler timings exclude kernel signal entry/return.
Steady read/write batches use `/dev/zero` and `/dev/null`; correctness checks
use real pipes. This crate requires a singleton with caller-certified immutable
code. It does not discover arbitrary ELF/libc instruction heads or implement
general thread, signal or executable-mapping lifecycle support.
