## Independent native oracle

[quiescent_oracle.rs](../tests/support/quiescent_oracle.rs) uses Linux ptrace
execution and architectural snapshots without decoding or emulating the
application. Original and patched sibling processes have identical application
code/data/stack addresses. The fixed corpus supplies instruction heads by hand.
It delivers owned SIGILL through the real handler and compares state at restored
original-instruction boundaries and the rejoin, using explicit generated maps.

Twenty required positive puzzles include all16 five-byte layouts, same-site
GPR/flag/data/red-zone changes, an interior rel32 entry, an upstream RIP-relative
prefix, and a padded qualified0x62 entry. Each declared entry runs with seeds
`0x1234567887654320` and `0xfedcba9801234567`: **160 entry/seed executions,
35 distinct routed heads, zero mismatches**. A separate upstream null-load puzzle
runs two seeds and requires matching SIGSEGV/SEGV_MAPERR, address0, logical
fault PC and full architectural state.

Comparisons include GPRs/RSP/logical RIP, defined RFLAGS, segment selectors and
bases, exposed CPUID-described user XSAVE components, every application-data
byte, application stack/red zone, and exact published code. Fixed masks exclude
debugger TF/RF and reserved XSAVE metadata; x87/SSE/AVX/AVX-512 data are seeded
nonzero, while permission-sensitive components begin in their initial state.
The declared instrumentation-private stack reserve is excluded. Six negative
calibrations intentionally corrupt GPRs, flags, SIMD, data, red zone or the fault
address; each must fail the corresponding comparator.

Review found that an invalid EVEX prefix near a page end may fault fetching
later bytes before raising #UD. Production now requires the entire architectural
15-byte fetch window within the authenticated snapshot and one executable page
before selecting0x62. The guarded page-tail positive regression requires0x60;
it was not converted into a refused or skipped case. The oracle's source-page
permission finalizer now runs before the publication receipt, matching the
production admission contract.

## Metrics and limits

`PlannedInstall::metrics()` exposes upstream bytes, displaced bytes, prefix
instruction count, allocation attempts and the complete attempted-site outcome
list. The RIP-relative upstream fixture has7 upstream bytes,9 displaced bytes
and one prefix instruction. Placement constraints are exercised with explicit
fixture regions; bounded search can legitimately exhaust elsewhere despite
available address space. Refusals are not positive coverage.

The recorded debug contract run had16 layout publication samples and68
cache/page samples. Their first publications took29.382ms and28.657ms; later
samples ranged18.888–41.042us and15.814–38.358us respectively. The guarded-tail
child's first publication took23.923ms. These include allocation/routing and
sync-core registration, run on a shared host without affinity, and are raw
diagnostics, not stable latency quantiles or a performance comparison.

RX mappings and immutable route/reverse-PC metadata currently live for the
process lifetime, including after retirement. Budgets bound each plan rather
than total process retention. Calls, x87 relocation, active CET, APX/MVEX and
unqualified instruction semantics are refused. Transparent application signal
frames/unwinding, general binary coverage, Intel qualification, T1/T2/T3,
coalescing/grouping, ELF rewriting and repeated toggles remain later work.
This fixed corpus supplies A1 evidence; it is not the later generated and
sampled-binary campaign or an all-ISA proof.
