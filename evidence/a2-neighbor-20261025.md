# A2 neighbor eviction and tactic selection — 2026-10-25

This partial A2 milestone adds T3 neighbor eviction and one install-once tactic
engine on an AMD EPYC Zen 5 dev host. A2 remains open for independent runtime
coalesced controls, classified search termination and the generated/sampled
campaign. Raw logs, captures, source hashes and review records stay in ignored/.

T3 preserves a whole 10–15-byte victim in a callback-free image. Its original
entry receives E9 to that image; a second E9 at victim+5 enters the selected
instruction's observing or replacing image. The selected 2–4-byte instruction
receives EB to that private source relay. Exact signed displacement limits put
the victim start from selected−131 through selected+124, inclusive. Both original
instruction identities come from the original snapshot. Unchanged tails remain
locked; later member reads authenticate the descending-address byte overlay.

Both images and source edits belong to one existing quiescent bundle transaction.
All images stage before source stores; postwrite failure poisons the lease and
retains reachable code and ownership. Retirement restores edits in reverse order
after draining the source and both images. This is not an atomic two-edit
publication claim. The immutable outer T3 geometry identifies the relay; internal
members use the trusted relocation contract. Source relays do not acquire
process-lifetime original-PC authority.

The engine tries generalized pun, ordinary relocation, prefixed pun, successor
eviction and neighbor eviction in that order. Forced selection invokes exactly
one tactic. Every winner is a bundle, including single-image plans, and pays
aggregate budgets. A successful leaf that exceeds a bundle limit remains an
engine failure. Complete ordered leaf attempts and winning metrics remain
available. Five bounded leaf invocations may repeat decoding; no search speedup
or complete search-termination classification is claimed. RapidProbe retains
its separate exact-byte toggle interface.

The T3 contract has 13 bounded child scenarios: 583 install/retire cycles,
7,002 native calls and 583 callbacks. Two additional B2 transactions only set up
ownership tests. Required positives include all 36 combinations of selected
length 2–4, victim length 10–15 and both signed endpoints; 384 cases cover every
cache-line offset for each selected length and direction. Another 144 cases
cross source cache lines or pages. There are 120 planning refusals, 24 BeforeWrite
refusals and four KeepGated injections. Forced victim selection, descending
automatic selection, total pair budgets, matching-snapshot ownership conflicts,
stale snapshots, allocation failures, retries and separate replacement semantics
have explicit assertions. Ordinary native positives execute four body entries;
the independent oracle below additionally executes all declared gap heads.

The first contract run exposed an incorrect test assumption that both generated
images always occupy one page. The corrected assertion computes each exact
page-rounded emitted extent, checks every declared allocation and the summed
virtual/backing charges and span, and requires exactly 18 two-page generated
images in the unchanged crossing cohort. No positive geometry, budget or
execution comparison was removed or relaxed. The initial failure is retained
privately alongside its correction and independent review.

The original endpoint oracle passed before extension: six layouts, 737 original
heads including every one-byte NOP gap, two fixed seeds, 1,474 installed and
1,474 retired full-state/event comparisons. Its execution body was then split
into six named tests with the same heads, seeds, comparisons and aggregate
inventory, allowing four test threads within the unchanged command budget.
The source owners remain pinned to prevent address reuse against retained code.

Nine additive fixtures cover selected self-LOOP, 10/15-byte victim self-LOOP,
10/15-byte conditional backedges, 10/15-byte RIP-relative loads followed by
stores, and 10/15-byte MOFFS faults. They require another 552 installed and
552 retired comparisons. LOOP seeds are derived by inverting the unchanged
register initializer to obtain RCX values 1 and 3; an executable regression
verifies those constants. Conditional backedges retain the original seeds and
require 32/31 selected visits. RIP data lies outside the scanned function but
inside the fully compared source page. The MOFFS witness completes with the operand
page readable; identical code and address then execute with that page protected,
requiring 120 SIGSEGV/SEGV_ACCERR comparisons per phase. Selected paths bypass
the faulting victim. Fault paths require no callback and compare logical fault
PC, address and full state; they do not claim ordered hook-event recording.

Relay validation independently recognizes exact literal MOVABS, JNZ, RIP-load,
MOFFS-load and self-LOOP grammars. A pristine native first step must agree with
the exact length; conditional witnesses must prove fallthrough. It verifies the
selected EB, both E9s, distinct image entries, logical ownership, unchanged tails
and absence of original entries inside the victim. At the relay it compares the
complete next logical state and prior event prefix without consuming a native
visit. The next hardware step must reach the selected image, and final counts
must match every selected visit. Twenty-four rejection calibrations supplement
the six existing oracle calibrations and two manually encoded positive relays.
The old comparator, masks, calibration assertions, 20,000-step bound and
15-second trace deadline remain unchanged. SHR's undefined AF remains subject
to the stricter native comparison; no new mask was added.

The engine corpus requires all five forced winners, three competing-tactic
rankings, natural fallback to T3, forced refusals and aggregate-budget refusal
after leaf success. Nine native cycles make 108 calls with nine callbacks.
Each winning contract, emitted image and PC map must exactly equal its directly
invoked leaf planner, followed by publication, original-entry execution and
retirement through the engine's bundle.

Independent reviews cover production, the contract and the oracle; authors do
not approve their own fixtures. The bounded runner records the four required
workspace checks and twelve focused commands with source and log hashes. It
retains four Cargo jobs, offline dependencies, disabled incremental compilation,
one target directory and 180 seconds per command. The T3 oracle has 50 Rust
tests, including its original shared calibrations; subprocess case summaries
are not additional Rust tests. Exact revision receipts remain private.

This is finite native qualification within the existing unsafe caller,
quiescence, ISA and lifetime contracts. It does not establish arbitrary victim
instructions, recursive eviction chains, Intel/CET support, asynchronous signal
or unwind transparency, concurrent toggles or workload performance. Generated
code remains retained for process lifetime. Selected fallthrough adds EB, relay
E9 and generated continuation; victim fallthrough adds entry E9 and generated
continuation. Original taken branches may bypass continuations. These transfer
counts are separate from timing measurements.
