# A2 literal exception landing entry

The workspace now includes an unpublished `liteinst2-exception-oracle` fixture
package. Its own build script compiles authored C++ and assembly using `g++`
(or `CXX`), libstdc++ and libgcc_s. The core library has no new build script or
dependency. This Linux/x86-64 fixture runs on an **AMD EPYC Zen 5 dev host**;
raw build logs, captures, manifests and failed attempts remain ignored.

An actual C++ throw reaches an authored assembly catch through its literal
LSDA landing entry. The test authenticates the LSDA, type and personality
references, instruction bytes and complete dedicated source page. It installs
a forced B1 relocation at the landing's five-byte NOP, then retires it under
a separate lease. Both leases end before admitted execution.

Two distinct integer exceptions execute in each of the original, installed and
retired phases: six actual catches, six landing visits, six search and six
handler personality calls. The installed phase requires exactly two callbacks
at the original logical landing PC, preserving the exception pointer and
selector. Independent prefix tracing adds two original, two installed and two
retired traces, twelve boundary snapshots and two exact hook-log events. The
existing architectural-state and full application-memory comparisons, both
seeds, 15-second per-trace deadline and 20,000-step limit remain unchanged.

Three exact planning refusals cover an interior-byte entry, incomplete entries
and unresolved resumes. Two publication failures require `BeforeWrite` for a
stale generation and changed source; the latter authenticates the still-stale
whole page before the fixture restores it. Every phase checks source bytes and
LSDA preservation, and installed execution also authenticates generated bytes.

The activated Cargo-produced target passes **14 tests: one native cohort and
13 existing shared-helper calibrations**, with no failures or ignored tests.
These duplicate calibrations are not additional exception cases. The focused
native process uses 20 CPU seconds, 30 wall seconds and 128 KiB output limits;
the owning supervisor proves that all children are reaped. Formatting and
workspace Clippy also pass. An initial formatting failure is retained; its
only correction expands one build-script assertion across lines.

The activated source and focused receipts are bound by private audit SHA-256
`51dccdb243d8fc8a4b118325a03dfe7f4a8cf5b5571e102925971aab6ea4e97d`.
The earlier standalone nine-test pass is preserved separately. Adding the five
existing parked-context calibrations accounts for the new target's count.
Only two shared-helper include paths change, resolving beside the helper;
removing those path changes and the new borrowed-text adapter recovers its
previous contents exactly. The adapter never unmaps linked executable text.

This qualifies the declared original landing entry. The unwinder reaches that
entry before instrumentation executes; the callback does not unwind. Unwinding
through generated trampolines or callbacks, publication during active unwinding,
arbitrary landing-pad grammars, active CET and Intel execution remain open.
This fixture does not complete A2 or establish general unwind support.
