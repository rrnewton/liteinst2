# A2 parked signal context and preserved CALL returns

These additive Linux/x86-64 fixtures run on an **AMD EPYC Zen 5 dev host**.
They retain the full architectural-state and application-memory comparator,
both established seeds, the 15-second child deadline and 20,000-step limit.
Raw source manifests, receipts and failed attempts stay in ignored evidence.

`tests/parked_context_oracle.rs` captures a real SIGUSR1 frame before source
publication. The handler first traps, calls the real publisher while the frame
holds the sole application continuation, then traps again before returning.
All seven original heads of the five-NOP/MOV/RET body are certified resumes.
The parent authenticates the whole bounded kernel frame, its extended-state
extent, source and generated bytes, permissions and publication receipt. The
frame must remain byte-identical across publication. No tracer register or
memory write intervenes after capture. Actual syscall entry and exit witness
rt_sigreturn, after which the unchanged oracle compares restored application
state and the complete original itinerary. Four interior displaced heads use
the production SIGILL router.

Every head executes with both seeds: 14 original traces, 14 child publications,
14 unchanged-frame checks, 14 real rt_sigreturns and 14 installed traces. Exactly
two selected callbacks and eight routed resumes are required. The complete
callback log is empty before delivery and after publication, so an early
publisher callback cannot substitute for application execution. Handler DF must
be clear before calling Rust; the saved flags and odd-DF seed remain unchanged.
Five additive rejection calibrations catch frame mutation, unauthorized source
writes, unchanged source after publication, wrong identity and failed status.

This is a closed, single-threaded fixture with no inherited publisher lock
holder. Its actual frame and success-only handler return path hold the lease.
It does not qualify arbitrary signal-handler publication or parked-context
retirement. Each child's installed handle is retained until process exit.

`tests/call_return_oracle.rs` preserves actual CALL RAX and CALL RDI at their
original addresses. Their helper RET returns into the unchanged displacement
bytes of a one-byte generalized pun. Each case enters every declared head
through an actual branch; exact itineraries include CALL, helper RET and the
original return head. The full stack comparison checks the pushed return word.
Only the selected NOP changes to E9, and all source and generated bytes are
verified. Retirement restores the complete original source page.

Eight heads, two seeds and two register variants require 32 original,
32 refusal-preservation, 32 installed and 32 retired traces, including 16 actual
CALL/RET paths per phase and eight installed callback events. The same window
under forced relocation must return the exact unsupported-CALL refusal, twice.
Those refusals demonstrate unchanged execution; they do not qualify relocation.

The initial CALL layout failed its required positive because the prescribed
image had only 100 bytes before a page boundary. Moving the entire source origin
by 256 bytes preserves all instruction bytes and relative displacements while
providing 3,940 bytes. The one-candidate, one-mapping, 4,096-byte budget and every
semantic assertion remain unchanged. That failure is retained. A separate
compiler preparation failure incorrectly applied the native output-file cap to
the executable; only the compiler artifact cap was corrected. Native limits
remain 20 CPU seconds and 60 wall seconds for that focused run.

The parked native cohort retains 20 CPU seconds, 30 wall seconds and bounded
output. Independent runner review found that nested process groups could escape
outer timeout cleanup; corrected private execution uses an owning subreaper,
with deliberate failed-watchdog and timeout calibrations. Earlier successful
native receipts remain preserved and are not used as failure-cleanup proof.

Removing the new oracle method and support imports recovers the earlier source
exactly before formatting. Earlier cases, masks and comparisons remain intact.
Repeated helper calibrations in additional binaries are not new semantic cases.
Full A2 remains open for exception entries, relocation-boundary signals/unwind,
active CET and Intel receipts, and eviction chains. General CALL relocation and
generated unwind registration are not qualified by these results.
