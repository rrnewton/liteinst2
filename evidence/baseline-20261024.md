## Architectural-oracle limits

Existing native fixtures check selected PC-relative results, entry visits,
callback counts, replacement behavior, register/flag/red-zone preservation,
SIMD/AVX/PKRU state, branch/call paths and a real synchronous fault. Kernel
register/extended-state capture already supports a focused ptrace-stop fixture.
Selected-output and replacement tests are not general no-op equivalence
oracles. CET relay decoding is not hardware-enforced CET execution. Tests that
return on missing capabilities do not prove those optional paths executed.
Encoding checks using the same decoder/emitter library are not independent
execution evidence.

A future oracle needs identical original/patched layouts and initial state,
every declared entry, independent kernel state observations, explicit mapped
instruction/rejoin boundaries, application-memory comparisons and synchronous
fault comparisons. Undefined state and permitted instrumentation-private
storage must be specified before comparison.

This baseline has no general per-boundary differential harness, complete
x87/SIMD/extended-state comparison across displaced heads, all-16-layout matrix,
or generated/sampled assembly campaign. Concurrent publication, signal routing,
CET and cross-host qualification require separate evidence. None of those
missing A1/A2 gates is claimed here.
