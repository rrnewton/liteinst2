# Finite E9 null-hook completion witnesses

`e9-null-witness.py` reads actual saved E9 products. It neither produces a
candidate nor maps, loads or executes one. It is a prospective input to a future
paired native adapter. A successful reader result alone is not native admission
or architectural equivalence. Current common-application E9 products and actual
reader outcomes are unbound and unrun.

The fixed denominator is the complete 87-head compiled kernel inventory:
174 normal one-instruction cases and both read-only store faults. The two
otherwise unreachable NOP heads remain. The original nine jump sites or one
heap-write site are a separate, complete static selection; their dynamic visit
counts never remove a case. Both stripped forms and both pinned E9 producer
lanes remain separate required cells. This reader supports null-hook witnesses;
recording-hook support remains required future work.

## Invocation and authority

```
python3 tools/elf-rewrite/e9-null-witness.py /ABS/inputs.json /ABS/NEW_DIRECTORY \
  --inputs-sha256 TRUSTED_SHA256
```

The caller creates and independently admits the exact input record before the
invocation. It has exactly `schema: 1`, `structural_envelope`, `instructions`,
and `target`. Each of the last three is a bound file object with exactly
`path` (absolute canonical path), `bytes` and `sha256`. The structural envelope
is the unchanged input of `e9-sites.py`: original and produced ELF, complete
selection and policy, exact lane's frontend/backend/loader, transport frontend,
helper and both complete requests/strict receipts/streams. No outcome or
authority is synthesized. Its original and policy identities must match this
reader's complete common-kernel selection. `instructions` must be the entire
hash-pinned 14-column table. `target` is the complete `LI2TARGET` record; its
exact compact projection must equal the selection's target line.

The reader holds canonical no-follow regular file descriptors and rechecks all
named paths, owner tuples and complete bytes. It reads the sibling
`e9-sites.py`, requires its exact approved SHA-256 and length, then loads those
verified source bytes in a private Python namespace. The existing main entry
point is not called. The existing structural validator, receipts, lane pins,
mapping parser, trap classification and site-wire producer are used unchanged.
There is no subprocess call, compiler, native producer or supervisor.
For a private proposal invocation, `--structural-reader /ABS/e9-sites.py` can
select that same pinned source at its retained coordinate. It does not alter
the accepted source hash, schema or predicates.

The output records the observed reader source hash/owner. That observation does
not prove which source the caller launched. The caller must separately bind the
reviewed reader source, invocation, complete exit/output and parent closure,
all inputs and the prospective native consumer. Neither an invented parent
record nor a reader-generated native permission is accepted. All results set
`native_admission: false`, `actual_runtime: null` and
`qualification_complete: false`.

## Actual image and operation proof

Whole structural authentication retains the E9 algorithm versus bootstrap ABI
lane distinction, complete requested outcomes, actual RPC intent and exact
loader bytes. RPC instruction records are not a complete original-head map.
They never establish replay coverage. The 87-row closed original table and
both exact prepared original ELF hashes supply that denominator.

The declared controlled page view first installs every actual candidate
`PT_LOAD` in program-header order, including the loader, then applies the
authenticated trampoline mappings and original RX refactoring overlays in the
exact emitted loader order. File-page prefixes and suffixes are retained; a
LOAD with BSS zeroes from its file extent through its final partial memory page,
matching the existing original-image adapter. Every final page binds its full
bytes, flags, source file offset, copied length, zero boundary and final owner
order. Overlapping initial LOAD pages, invalid overlay ownership, writable
generated code, non-low-canonical ranges, seed guard collisions and the fixed
page bound refuse. This is an explicitly reconstructed image; it is not proof
that the normal loader ran. Dynamic relocations and interpreter startup are not
emulated. The fixed original hashes and original-image admission separately
retain the kernel's no-dynamic-relocation/no-RIP-relative-data boundary.

Each head begins at its exact original PC. If its complete original instruction
remains there, that is its operation. Otherwise, only exact unconditional
`EB` or `E9` transfers, with the pinned ordered redundant prefixes, may be
followed. Every prefix edge has literal bytes and a single predicted target.
The reader never searches other addresses or executes trial instructions to
find an equal state. A repeated PC, unsupported edge or missing original
operation is required unresolved.

A relocated body must lie in one actual executable trampoline owner. The
reader independently recognizes the finite pinned relocation rules against
the original bytes:

- ordinary instructions, including RET and both NOPs, retain all bytes;
- the four present short Jcc conditions become the exact corresponding near
  Jcc to the original target; short JMP becomes near JMP to its original target;
- a relocated direct CALL is exactly a signed-imm32 PUSH of its original
  `pc + 5`, then a direct JMP to its original callee. The six return words are
  `0x401878`, `0x401886`, `0x401902`, `0x401927`, `0x401935`, `0x401942`.

No arbitrary CALL encoding, address normalization, additional memory scratch or
register repair is admitted. Exact unchanged original CALL bytes are also valid.
For each selected site, the reached body and complete null-template extent
must equal the actual structural trampoline record. Evicted, unselected heads
use their independently reached bytes and owner; their presence in RPC rows
does not stand in for a witness.

Both selected and eviction null templates contain an exact continuation E9.
Its destination is the original fallthrough, or an exact recorded bypass whose
unconditional byte path is independently followed from that fallthrough.
All bypass records must be accounted for. The continuation is recorded but is
never part of the current operation's completion. In particular, a MOV followed
by an original JMP completes immediately after the MOV, even if `$continue`
would bypass that following JMP. The physical endpoint is established before
replay, not selected after comparing states. A relocated CALL completes only
after its JMP has reached the callee, with the original return word on stack.

After all heads resolve, every original page is compared with the final view.
Only the structurally authenticated ELF entry/PT_NOTE change and actual
gateway bytes inside the three closed kernel ranges may differ. Whole globals,
journal, other text, BSS and page permissions remain exact. A gateway cannot
grant new source write ownership. Unaccounted changes or bypasses keep the
complete result unresolved.

## Record and future native boundary

Four exclusive output files are written: `witness.json`, unchanged-format
`sites.tsv`, the fixed native projection `native.tsv`, and their `files.json` index. The JSON is deterministic, newline
terminated, and carries the input owners/whole hashes, complete structural
result, mapping order, final pages, 87 heads and 176 cases. It is private
evidence: input paths and owners must not be copied into public reports.

Each head contains its original bytes/geometry, ordered prefix, restored body,
one or two operation instructions, separately checked continuation, and exact
status/reason. Each case binds the original seed index/value/flags, exact
operation edges and predeclared physical/logical completion. Jcc outcomes come
from the two frozen flags states. RET returns to the seed's exact owned return
PC. The two store faults require SIGSEGV/SEGV_ACCERR at A+8 or A+24 and retain the
body PC without advancing. They do not convert a fault into normal completion.

Exit 0 means all byte witnesses and source checks were constructed. Exit 2
writes `REQUIRED_UNRESOLVED` with all 87 heads and 176 case identities retained;
it never grants partial replay admission. Every selected trap or refusal blocks
eligibility. Malformed or unauthenticated inputs fail with nonzero exit before
publishing an authenticated output. The calling recipe must preserve that
failure and all unrun rows. A missing or partial index is never complete evidence.

Before native consumption, a separately reviewed consumer must reconstruct the
same whole page view, independently check each prefix/operation byte and exact
physical edge, retain all 176 seeds, and check physical RIP before applying the
declared logical boundary label. It must keep the existing full GPR comparison,
TF/RF-only flags exclusion, full canonical XSAVE, entire data page and fixed
`[E-128, E+32760)` application stack, plus whole saved stack/global/journal
evidence. CALL return words and memory bytes are never normalized. This reader
does not implement that consumer or replace those checks.

The prospective reader bounds are 16 MiB per input, 2,048 final image pages,
32 prefix edges and at most two operation edges per case. They are not observed
result counts or permission to raise a cap after refusal. Existing native
15-second/20,000-stop limits remain unchanged. A later E9 replay recipe must
freeze its own complete capture/resource inventory from these exact mappings;
core-null capture counts do not transfer. No ordinary rewritten execution,
normal-loader coverage, benchmark, performance or full-A3 claim follows.


## Native projection successor

`native.tsv` is a bounded, ordered projection of the same complete canonical
JSON record. It starts `LI2COMMONE9NATIVE\t1`, retains the status and hashes,
and binds the whole `witness.json` bytes by SHA-256. The output index binds
both files. The caller must authenticate both files and the actual reviewed
reader invocation before a native consumer uses them; a hash-shaped string
alone is not authentication.

On complete witnesses it contains all 23 named held input owners (canonical
filesystem path encoded as raw-byte lowercase hex), all actual PT_LOAD rows,
then actual loader mappings in their original order, every final page owner,
87 ordered head/prefix/operation/continuation records, and 176 ordered seed,
operation-edge and completion records. All numbers are decimal; absent
completion fields are the literal `none`. The final row is `complete 87 174 2`
with tabs. Continuation/bypass records remain authentication data, never an
operation-completion substitute. The native consumer can parse these fixed
rows without a JSON parser or new dependency.

An unresolved witness instead ends `required 87 174 2 UNRESOLVED` with tabs.
It has no runnable head/case projection. This does not discard the unresolved
JSON head inventory: all 87 heads and 176 mandatory cases remain in the JSON.
The new projection changes no producer, byte-witness, selection, target,
loader, opcode, outcome, bound, cap or comparison assertion. No native result
or caller permission is generated by either output.
