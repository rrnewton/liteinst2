# Scalar region decoder qualification

Run only from the committed revision being qualified, on one externally
reserved CPU:

```
python3 evaluation/inprocess/region_decoder_qualification.py --expect-revision FULL_REVISION
```

The eight fixed processes retain the original decoder limits: 3 CPU seconds,
10 wall seconds, 256 MiB address space and 1 MiB file/capture. The original
112-form supplied controls, actual exhaustion102, actual personality106 and
freestanding seven-class/4110-start harness are linked unchanged. A failure
does not reduce the population, raise a cap, select a replacement, or receive
overall qualification credit. Continuing requires actual reap and complete
descriptor cleanup. First error remains authoritative.

This evaluator explicitly selects the `scalar-region` decoder feature. The
shared builder's default still compiles exactly the original eight source
files without the descriptor export or its factory initialization. The new
profile requires exactly nine files and one descriptor export, and pins the
actual Cargo feature resolution. Both the production and separate test
archives for this cohort use that same explicit feature.

The production archive supplies two new processes. The first constructs
3898 accepted encodings in nine fixed groups and checks them forward and
backward (7796 calls). All 304 bytes are compared against an independent
encoding/form model. The embedded72 bytes are separately joined to the old
decoder API; fixed Code IDs bind the locked iced-x861.21 enum. The model keeps
E32 reads/R64 writes separate, duplicate operand aliases, XOR-self clearing,
all flag categories including undefined AF, memory segment/base/index/scale
and displacement, exact branch condition/target, and all zero/reserved bytes.
It then requires33 exact literal refusals,124 proper-prefix truncations and
six argument-refusal checks. These are actual describe calls, not changed
expected answers or cached decoder results.

The second process places all47 base forms and their124 proper prefixes at
the last readable bytes before a real inaccessible page. Every171 call must
return the complete expected result; an over-read signal is a process failure.
NOT_READY, repeated initialization and whole owned-output initialization are
also checked. No supplied instruction bytes execute in either process.

The last two processes use a clearly separate retained test archive. A copied
crate has identical original source/manifest/lock bytes, except two appended
exports. One holds the real arena call token while invoking the real public
descriptor API: BUSY and all304 zero bytes are required, followed by a genuine
successful call after guard release. The other makes a real valid allocation
request through the actual global allocator after sealing; exact fatal101 and
exit125 are required. The production archive contains neither test export.
These controls qualify real guard paths in that marked artifact, not new
production exports or direct fatal-deallocation103 coverage.

The complete actual allocator tuple must remain unchanged after every matrix
group, both passes, and the remaining successful calls. It stays phase2 with
no fatal reason and within the original16MiB arena. The separate source proof
of at most three register/one memory rows for the47-code domain remains
necessary; warmup or these finite rows alone do not establish allocation-free
behavior for arbitrary future decoder domains.

The driver closes all source/tool/registry/actual compiler include inputs,
both archives, dep-info, executable/library identities and retained captures.
Each genuine accepted result receives strict supplied-output controls (104
total); these add no subjects. Public JSON/CSV retain summary numbers and
receipt hashes, without per-descriptor logs. Native execution of original and
generated regions, full GPR/AF/FP/stack/data/fault equivalence, and runtime
source/owner authority remain separate required qualifications. Duration is
not a workload speed measurement.
