# Retained REP lease component oracle

This additive oracle exercises the actual owner, source custody, lifecycle,
registered-rseq guard and RAW gateway. It does not replace the original STOSD
or STOSQ oracle. Those four positive/fault processes remain required separately.
The new command is `python3 evaluation/inprocess/page_selected_repeat_lease.py
--expect-revision FULL_HEAD`, under one reserved CPU and the original process
owner. The evaluator rebuilds the current release archive and the finite
fixture, authenticates every conditional compiler dependency and actual ELF
and file-only DWARF, and runs the fixed OUTCOMES population once each.

The finite fixture explicitly enables `LI2_FAST_EQUAL=1` as its fifth macro,
after the same effect, registered-rseq, maps-reuse and REP-lease macros. This
exercises both complete word-plus-tail zero predicates and the existing exact
fast-equality implementation in the actual owner translation unit. The five
instrumented views still use the same ten reversible edits; only the two
changed runtime include facts are refreshed. All 46 cases, full-state readers,
supplied controls, output and process limits below remain required. The earlier
`17b3adf00603` attempt failed before any native subject because those source
facts were stale; it remains failed. This source update grants no execution or
performance credit.

The 46-process required population is fixed before execution:

- Eight registered positive processes cover width4/8, DF0/1, and either three
  counts0/1/3 or one count24:16 independent same-address native/owner pairs.
- Three fallback processes each compare both widths (anonymous source, an
  instruction crossing a page, and a one-page instruction with an actual
  15-byte/two-page borrow). One unregistered process compares both widths.
  These add8 pairs; no fallback is counted as a retained lease.
- Two genuine later-store faults start with RCX24 and complete exactly three
  stores before reaching a read-only adjacent destination page. Native and
  owner fault states are compared with the exact owned TF distinction.
- Four real self-tgkill deliveries occur at observed SEEDING, ENTRY, RETURN,
  and final REVOKING seams. The retained raw outer and incoming SI/UC/FP
  objects are joined to each actual phase. ENTRY before the owner consumes
  the outer TRACE is honestly `unexpected`, not relabelled owner `nested`.
- Twenty-eight supplied negative processes test copied owner, replayed ticket,
  changed source/pin descriptors, actual nonzero rseq word, dynamic rseq
  overlap, post-TRACE count overflow, and four explicitly nonissued
  cleanup-result injections; sixteen of these cover partial private overlap

Every successful native/owner pair retains all sixteen GPRs, all23 kernel
register fields, whole flags, complete initialized kernel FP plus its unused
zero tail, independent live standard XSAVE, all six live selectors, the whole
8192-byte target stack and all four destination pages. At each actual TRACE,

Cold and intermediate post-handler_end snapshots are actual observations,

Actual FS/GS base queries occur only at empty-borrow outer boundaries. No
per-TRACE base value is inferred from ucontext or selectors, and the retained
snapshot helper performs no syscall.

Hardware TRACE progress is checked against the independent literal STOS
model; it is not assumed that every element generates one trap. The count24
positive cases must actually retain RX across at least one intermediate TRACE.
The final TRACE must perform the one real revoke/sync/closed continuation and
release, and the original next-PC must subsequently cause genuine NX. Old
fallback still closes/reopens on every TRACE, with its initial registered-rseq
