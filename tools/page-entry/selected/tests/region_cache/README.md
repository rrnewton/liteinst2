# Closed read-only CFG component experiment

This additive component asks whether one authenticated region can execute ordinary loads, arithmetic and direct linked branches with constant entry/exit events. It does not qualify arbitrary application CFGs, libc/ld.so coverage, whole-bridge integration, rseq, asynchronous application handlers, fault resumption or a whole-`ls` speedup.

The C owner calls the unchanged public `plan_whole_function_controlled_detailed` through a small Rust adapter. It preserves the core's complete 5..80-byte closed scalar function, leader, no-resume, Legacy128, System V/no-CET, one-image/8192-byte and allocation-search contracts. There are no core API or refusal changes. Entry and RET controls are distinct, disabled managed controls whose writers are destroyed; their plan and metadata remain alive until generated RX is revoked, synchronized and unmapped. All actual callbacks must remain zero. The original page remains NX in the cache lane. No source patch or interior SIGILL route is installed or relied upon: this sole-entry, no-resume caller excludes original interior entry.

`plan.h` is an unsafe caller contract, not a runtime permit. The owning fixture separately establishes singleton/no-debug state, successful registration followed by actual rseq unregistration, default reserved dispositions, blocked asynchronous signals, guarded alternate/application stacks and no CET. Entry RSP is 8 modulo 16 with a real guarded return word. The 128-byte application red zone and the 24 bytes above the return word are preserved; deeper private helper stack is explicitly available to the existing Legacy128 emitter. Application data is a fixed 32 KiB buffer read only by the region, and no concurrent/foreign writer or remap exists in this finite profile.

Source identity is SHA-256 of the fixed policy string (including NUL), complete-function length and complete original 4096-byte source page. It is bound to the actual sealed memfd inode and non-reused generation. The custom publisher writes each memfd before sealing with all four seals, maps only private R/RX, and authenticates complete bytes, exact FD/stat identity, seals, file offset, actual permissions and a unique whole mapping with no alias. Actual private writable aliases of both sealed backings must be rejected, actual pwrite attempts must return EPERM, and stale generation/object/offset/protection descriptors must refuse: eight authority controls per process. These supplied controls earn no native-operation credit. Every return/fault boundary rechecks the original source owner. Failure retirement attempts every revoke, sync, unmap and close independently while retaining the first error. Plan destruction cannot precede executable-image retirement; in a signal-terminal failure the plan remains retained until process death. Successful cleanup here refers to both owned executable/source mappings and their descriptors; remaining fixture/observer allocations are reclaimed at process exit.

The source function is literal `XOR EAX,EAX; TEST ECX,ECX; JZ ret;` followed by one, two or four unrolled instances of `MOV RDX,[RSI]; ADD RAX,RDX; XOR RAX,R8; ADD RSI,8`, then `DEC ECX; JNZ loop; RET`. The independent Python reader checks the exact original page, content identity, every emitted ordinary body, branch target and PC-metadata bound, complete wire/padding, literal input model and full result. It does not treat planner success as native evidence.

Each of the nine positive processes uses one fixed unroll in 1/2/4 and trip count in 1/16/256. All three lanes execute identical input/trips: original RX with a guarded exit; generated sealed region with original NX; and the actual unchanged `li2_tf_owner` over original instructions. A real unchanged NOP owner selftest precedes them. The field `cold_ns` means the first observed invocation of that lane, not cache-cold latency: setup and the owner selftest already touch source/runtime state. Each lane has one first-invocation measurement plus ten hot invocations, interleaved by lane; all 270 hot timings remain literal, with median and inclusive quartiles. Complete GPR/flags, six selectors, all 32 live ZMM registers/eight K registers, x87 FCW/FSW, all enabled standard XSAVE bytes, complete kernel FP frames, FS/GS and logical application stack/data are checked before timing is credited. Unsupported hardware/state refuses.

For `N = 4 + trips*(4*unroll+2)`, every positive invocation must show exact `(NX,TRACE,completed-instructions,guard-exits)` counts: original `(1,0,0,1)`, cache `(2,0,0,1)`, TF `(N+1,N,N,1)`. The complete physical handler count is `3 + 11*(2*N+4)`, including the three-event startup selftest. Thus event scaling is directly falsifiable, not inferred from timing. Maximum N is 4612; the largest process requires 101,511 handlers and retains the same 5 CPU/15 wall limits. Whether ten TF samples fit those limits is an actual qualification obligation; timeout is failure and does not authorize reducing the population.

Two additional processes require a real inaccessible first load: one generated-cache fault and one actual TF-owner fault, each compared against a real original-PC fault reference. The generated PC must be the unique emitted body head for the original three-byte load, with exact bytes and unique PC-map association. Full actual fault GPR/flags/FP/memory and original logical PC are checked, with only the explicit generated RIP translation and the TF owner's actual TF bit distinguished. These invalid-pointer probes are outside the core's successful valid-pointer premise. They revoke and terminate with 125, count zero completed operations, and never invent an after-state or resume an application fault. All other unexpected events remain failure.

Run after source review/installation at one committed revision and one reserved CPU:

```
python3 evaluation/inprocess/page_region_component.py --expect-revision FULL_COMMIT
```

The evaluator reuses the existing committed decoder Build and actual bounded process owner, then builds the exact core as a separate cdylib and links the unchanged step-owner TU. The component enables the existing production fast equality path and uses the production bridge full-range `cld; rep stosb` reset, preserving all requested bytes and state comparisons. The initial scalar-reset cohort at `510e75cf0b5e26ceea133c1e6bfb8005141e736e` failed at its sixth case; that failure remains recorded with all unexecuted cases. These helper choices do not alter the population or resource limits. Source, Cargo registry, tools, actual compiler includes, runtime loader libraries, artifacts, aliases, all captures and final cleanup remain bound. Every subject is limited to 5 CPU seconds, 15 wall seconds, 512 MiB address space and 16 MiB file size; stdout/stderr capture is 65,536 bytes. The fixed 912,824-byte private record contains actual state. Public output is at most 32 KiB of numeric results/digests and contains no raw states or host paths. Existing build/metadata limits are reused unchanged. All eleven process outcomes remain present even on an early failure.

Preparation time includes source construction/sealing/hash, actual core planning and generated image publication; it excludes earlier process/hardware/fixture setup. First/hot invocation clocks include machine capture and required signal/owner work. They are component measurements, not pure instruction times or whole-process throughput. No speed threshold, overhead subtraction, unsupported-workload replacement or real-application coverage inference is permitted.
