# Finite CPUID-NX qualification

This source-only fixture qualifies the separately reviewed `LI2_CPUID_NX_ONLY`
native-page profile. It has not been compiled or run. The profile deliberately
excludes one-shot source publication. It does not complete B2, establish
arbitrary-entry coverage, or qualify other selected-class callbacks.

`page_selected_cpuid_nx.qualify(builder, products, root, private, pin, binary,
aliases, run, receipt)` reuses the configured-provider evaluator's current
Build, retained archive, bounded invoke and final custody. Call it only after
that same run's unchanged 385-provider and 51-callback cohorts pass. Keep the
original four carrier pairs and their six-owner predicates in their original
profile. Add `BOUNDS` to the parent bounds, invoke `finalize(receipt)` before
every child and from the parent final closure, and add `summary(receipt)` to
the public result. The parent must retain its exact revision, hardware, tools,
compiler-selected dependencies, loader-configuration presence, command/capture,
source, alias, partial-artifact, cleanup and first-error checks. No new receipt
or process-launch framework is provided here.

Before building, `prepare.py` requires every exact fact in
`PREREQUISITES.json`: NX R1, the explicit provider composition, both recipes,
and the corrected shared library reader. Merely defining the macro over the
old faulted source is rejected. Observation inserts six exact snippets and
inverts them to the complete actual runtime/controller bytes. No permission,
decoder, callback, source or frame repair is inserted.

The six fixed programs each run in five lanes: native, faulted/raw,
faulted/configured, NX/raw and NX/configured. CPUID is the genuine first
interpreter and first main instruction in every program. Later seeded routes
cover both two-byte fetch tails, direct/indirect/RET entry into a MOVABS
immediate and its enclosing instruction, a page-ending CALL/return, a real
3+7 MOVABS retry, an ordinary TRACE predecessor, and a completed two-MOV copied
run ending at the original CPUID guard. The helper and native predecessor
pages must pass the existing all-byte scan including both 14-byte halos.

The observer copies the actual kernel ucontext, full bounded FP image, complete
64-KiB source, interpreter page and 32-KiB data/stack before and after every
selected effect. It requires exact architectural CPUID writes, original PC+2,
unchanged nonoutputs and memory, and literal seeded flags/GPR/all32-ZMM/all8-K
state. The source program independently captures all live GPRs, flags,
selectors, ZMMs and K registers after sigreturn. Its complete 9,728-byte output
must equal native, except the three explicit configured feature bits. This is
not an independent whole-live-XSAVE oracle: full kernel FP equality and live
vector/mask capture are complementary observations. First-entry inputs are
actual inherited values, not invented seeds or cross-process equality claims.

Additional actual processes preserve failed-operation labels:

* Twelve outer seccomp controls deny GET_CPUID, SET_CPUID, or both. Six NX
  executions must complete; six old faulted lanes must retain failure236/238
  before target entry. The filter's actual installed instruction list is
  checked exactly. Positive NX output must also equal the native reference.
* Eight application GET/SET controls must fail205 before forwarding, with
  complete captured effects before the denied operation and no following
  marker write. These are refused operations, not successful program runs.
* Two ancillary bootstrap controls execute a real SET_CPUID(0) immediately
  before the original bridge entry, without intervening exec. A genuine #GP
  must identify the first retained bootstrap CPUID, with no target entry.
  The tiny entry shim is a control, not the production fresh-exec lane or a
  claim that a kernel lacking CPUID controls has been tested.
* The original native-page boundary assembly/linker execute unchanged in all
  five lanes. Its full 128-byte equality, four main admissions and one main
  refault remain mandatory, with the original complete chain/register/rseq
  closure functions and the actual launch PID.

There are 57 planned processes: 41 successful programs and 16 expected failed
operations. Every process retains 30 CPU seconds, 60 wall seconds, 512 MiB AS
and 16 MiB file/capture bounds. Parser acceptance of a failure prefix is never
completion. NX reports use actual attempted/sampled/committed phases and
builtin phase0; the old faulted lane retains real phase7. No phase or admission
counter is normalized into the other profile.

The existing RF/NX, raw-policy, gateway, generic/TRACE/register, rseq and real
five-case application matrix remain separate mandatory qualification. Later
combination with source publication requires its own reviewed lifecycle and
restored-ingress composition and both complete corpora; removing the current
compile-time exclusion alone is insufficient.
