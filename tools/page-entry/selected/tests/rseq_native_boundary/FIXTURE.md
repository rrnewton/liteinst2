# Four registered current-PC boundary pairs

The separate boundary evaluator retains the old sixteen-case profile and its required refusals. These four additive subjects use the same original ELF in native and gated lanes: split `MOV RBX,RAX`, split direct CALL, direct CALL ending exactly at the boundary, and a genuine rseq abort whose current kernel PC is fourteen bytes before the original fetch address. The last descriptor includes its publication instruction and places the signed abort target outside its critical interval.

Native reference handlers use actual mprotect calls and unchanged sigreturn frames to obtain the first and second NX events. The ending CALL has no refault token: its real pushed return word and restored RSP are checked at the callee and return continuation. No CALL is reconstructed. The three other cases require one completed registered retry each. Ordered native and gated observation counts are 3, 4, 2 and 3; every subject must exit zero. Missing events and unexpected prefixes fail.

Each record retains complete before/after signal UC and FP bytes, all six source pages, the complete 16 KiB data/stack image and the real rseq page. The reader checks independent register/vector/mask/flags and memory expectations, exact single CALL push, current abort-PC behavior, the actual old typed footprint guard, both real close records, token consumption and full cross-lane FP/UC conservation. Actual live selectors remain separate from reserved signal fields. The native lane installs the same application signal mask after its supervisor has independently recorded initial mask zero. No terminal data, unused capacity or failed prefix is silently dropped.

The existing singleton, actual CPU, mapping, source, signal and rseq restrictions apply. The original five-application matrix is still required; these finite cases do not establish general critical-section support or application completion. No instruction, tolerance, refusal or execution bound in the old profile is weakened.

Build and custody use the existing evaluator helpers, one reserved CPU and the original 5 CPU-second / 15 wall-second / 512 MiB / 16 MiB subject limits. All ELF geometry, dynamic dependencies, complete record extents and headers are checked after actual compilation. Source review or supplied reader controls carry no emitted-code or native-execution credit.
