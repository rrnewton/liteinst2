# Registered-inactive application qualification

Run `python3 evaluation/inprocess/page_selected_rseq_application.py
--expect-revision FULL40` with one externally reserved CPU. The evaluator builds
the current committed product and retains its seven outputs before linking the
test bridge against that exact decoder archive. All inputs, compiler headers,
lexical aliases, commands, process cleanup, records and artifacts are checked
again at closure. No ignored source directory or historical archive is needed.

This is the portable form of the qualified V4 finite fixture. Its image bodies,
observation C/header, six adapters, 17 outcomes, complete record comparator and
native/process bounds are unchanged. Two fresh-exec applications genuinely
register and unregister; both execute and observe a registered two-MOV cache
run. The other 15 applications must fail before their named operation, with
unchanged actual context/publication word and no new RX or matching raw call.
Their native references stop before the forbidden operation. They are not
native executions of a critical section or successful rejected operations.

The 52 cohort commands remain one image generator and 17 native, carrier and
gated commands. Native bounds remain 5 CPU seconds, 512 MiB address space,
16 MiB file size and 15 seconds wall time. Successful outputs are exactly
512 bytes; each gated observation record is exactly 13,312 bytes. Full pages,
contexts and command logs stay private. The public JSON contains numeric case
outcomes, counts, revision, hardware, reproduction command and private hashes.

The test builder copies authenticated current runtime sources and applies
ADAPTERS.json before adding observe.c/h. These adapters only observe genuine
dispatch/terminal events; they do not alter guards, results, frames or cleanup.
The fixed application addresses and fd3 observer belong only to this test
bridge. `build-rseq-inactive.sh` and `page_selected_rseq_real.py` use the
unobserved production sources and never apply these adapters.

The preceding V2 first-case cache-use failure remains failed. V3's unsupported
generator helper call was corrected by the exact R12 RIP-relative store in V4;
neither failing predecessor receives execution credit from this successor.
The portable package still requires qualification at its own committed source.

This profile excludes active critical sections/abort handling, threads,
fork/exec continuation, unsupported write footprints and unmodeled kernel
outputs. It does not establish complete B3 or performance. Existing full
architectural instruction oracles and old reference profiles remain required.
