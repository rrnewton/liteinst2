# Ordinary callers

This qualification uses the unchanged FreeBSD `strnlen` source pinned in
`../strnlen-work/UPSTREAM.json`. The separate `caller.c` is application code:
it makes two ordinary function-pointer calls, stores both results, and returns
their sum. It contains no profiler include, TLS access, assembly or SDK call.
Its two CALLs have different original continuation addresses. In its optimized
body RBX holds the first result; it is not a profiler scratch pointer.

`LoadedNormalLeaf`, `NormalSitePreparation` and the normal-thread attachment
form a separate profile. They share the existing full ELF/CFG and publication
checks. They do not use or relax `CallGate`, the fixed fixture terminal, the
optional pre-context stencil, or any existing profile's caller contract.

The runtime observes the actual entry and each original RET. It saves the
original RSP/return word without modifying them. At pre-RET it retains the
original model receipt and timestamp. The next authenticated entry confirms
the previous return under the explicit ordinary-CALL/no-reentry/no-nonlocal-exit
contract, then completes that original receipt before selecting the new owner.
The final pending call needs an unsafe same-thread checkpoint after application
work returns. Records distinguish these acknowledgements; neither is labelled
an independently observed physical RET. The native oracle must separately
observe the real CALL, C3, continuation and outer return.

The runtime performs no per-call or checkpoint file, mapping or input scan.
Continuous immutable-source and valid-input custody remains an unsafe caller
obligation. The qualification consumer checks the complete guarded input,
source pages and generated bytes before acknowledging/exporting a batch. A
failed check withholds the checkpoint. Pre-RET state alone cannot release the
pending model receipt, and abandoning an attachment cannot invent completion.
Metadata reports and checkpoints never authorize unmapping; code owners remain
process-lived.

The initial envelope is one actual attached thread and one complete 5..=80-byte
scalar read-only leaf with no CALL or edge back to entry, at most four ordinary
RETs and at most 32 calls between drains. Signals, recursive or tail entry,
nonlocal exit, cancellation, fork, active CET, source writers and unload remain
outside its unsafe contract. This removes per-call SDK invocation for that
envelope. It is not A5's complete real-application, browser or accuracy result.

The caller fixture is compiled with:

```sh
gcc -O2 -fPIC -fno-stack-protector -fno-asynchronous-unwind-tables \
  -fno-unwind-tables -fcf-protection=none -Wall -Wextra -Werror \
  -shared -nostdlib \
  -Wl,-Bsymbolic,--no-undefined,--build-id=none,-z,relro,-z,now,-z,noexecstack \
  tools/rapid-profiler/normal-work/caller.c -o caller.so
```

`caller_bytes.rs` pins its entire optimized 67-byte body and exact decoded
instruction heads. This is a qualification fixture constraint, not a runtime
allowlist of caller return PCs. Its four saved registers plus alignment slot
put each subject entry 48 bytes below caller entry RSP. Full state comparisons
therefore include the stack from caller entry RSP minus 176 through the end of
the admitted stack, preserving the subject's entire 128-byte red zone.

No performance or timing-accuracy result is claimed by this qualification.

`verify_normal_interval.py` runs the existing named, selected and whole-function
qualifications fresh at the requested clean revision, then reuses their
authenticated release binaries for the new controls. The native population is
16 stable pairs (two seeds by eight inputs), plus one separately labelled pair
that switches epochs while the calling thread is stopped at the first real
subject RET. The controller helper runs concurrently, outside single stepping;
the calling thread retains the original 15-second pair deadline and 20,000-step
bound. Each pair compares all 24 caller heads and both complete subject paths,
including the full protected stack and data page, and observes both target
CALL/RET transfers and the outer caller RET. The extra pair does not replace
any stable case.

Two additional functional processes exercise safe handle abandonment after
actual C returns, followed by the calling thread's real TLS exit. A pending
sampled receipt must keep its report unavailable. A pending FunctionClosed
receipt must retain its epoch permit even after the controller retires the
epoch and drops its report. Neither process calls the checkpoint; both require
same-thread reattachment refusal and an actual worker join. These are lifetime
controls, separate from successful record export and native state comparisons.
