# External request sessions

The `ordinary-interval normal-session CANDIDATE FINAL ELF_VA LENGTH K EPOCHS`
command profiles an admitted FreeBSD `strnlen` through ordinary C ABI calls.
The independent final ELF bytes and complete function extent use the same
unsafe loading/publication contract as the normal-caller qualification.
There is one attached calling thread. It invokes the function directly, with
no per-call profiler API. Two permitted CPUs are required.

Send ASCII LF-terminated commands on stdin:

```
CALL 42 3 610062
FLUSH 900
CALL 7 0 -
FLUSH 901
STOP
```

Each CALL makes exactly one actual call, including bound zero. The bound must
be no larger than the supplied bytes; at most4096 bytes are accepted. Hex is
lowercase, even-length, and `-` means empty input. IDs are canonical unsigned
64-bit integers, globally unique across CALL and FLUSH; they need not follow
invocation order. The session accepts at most4096 CALL/FLUSH commands. A parsed
valid command is accepted only when its complete input and ledger entry are
owned. A full four-command worker FIFO leaves one additional accepted command
in the controller's pending cell. It is retained until transfer succeeds.
Malformed or duplicate input fails the session. EOF before explicit STOP or
scheduled shutdown also fails; close the session explicitly.

The worker drains after four returns, and also before waiting on an empty
request queue so a lone returned request gets its result. FLUSH is a FIFO barrier:
it checks source/generated bytes and complete guarded inputs, acknowledges
all preceding actual returns, and exports a partial batch if necessary. An
empty FLUSH produces no new batch, ordinal or sample. The unsafe checkpoint
records a caller attestation, not an independently observed physical RET.

Epochs run independently of incoming requests: K is10 or1000, and EPOCHS is
1..4096, at10 ms intervals under the existing2 ms arm-lateness bound. Ordinary
calls keep running after K closes sampling. The controller uses the existing
Clock policy, with no missed-arm catch-up or deadline extension. Explicit STOP
is an earlier-stop run; it is never counted as a full scheduled campaign.
During the finite timed portion the controller actively waits in slices of at
most 1 ms. Each slice has one fixed target; the complete nonblocking event loop
runs between slices. In a 2 ms guard before the next original arm or end it
polls without a slice, using the unchanged lateness duration. This policy can
occupy one controller CPU. It removes deliberate sleep and wakeup from the
timed portion, but cannot prevent preemption or excessive application work;
a missed deadline still fails. Shutdown retains the original sleep policy.
This is not a real-time or low-overhead scheduling guarantee.

The last removal and shutdown retain the original strict2 s bound. The
520-epoch campaign requires521 actions; streaming history preserves their
absolute positions through explicit bounded history drains.

## Epoch storage

Before activation and Ready, the session prepares three fixed storage banks
with A=K. The two-worker sessions prepare four with A=4096. Each bank holds the
function, admission/terminal and payload vectors. Preparation initializes and
touches their slot state; it does not pin pages. No replacement banks can be
created, and ordinary allocating staging is refused in this explicit mode.

Each prepared stage creates fresh ownership shells and a fresh generation.
Reclamation requires a closed, noncurrent epoch with zero reservations and
exclusive ownership of both the frontend and model Arc. A retained Report,
admission handle or pending return receipt prevents reuse even when the
reservation count is zero. The consumer copies and checks each final Report
once, retaining its output
obligation while another owner delays reclamation. After all owners release,
reclamation clears every slot and returns the same vectors for another epoch.
History positions, worker identities and completion sequences keep advancing.

This removes recurring allocation of the three vectors. Two Arc allocations,
full-vector clearing, report copying, locks and history/output work remain.
Work performed by an arm still precedes its original completion timestamp; the
2 ms gate is unchanged. Storage reuse alone supplies no latency guarantee.

## Results and completion

Output is typed CSV with a4 MiB total limit. READY declares the version,
K/epochs/period/lateness/command/input/FIFO/reply bounds. RESULT contains ID,
ordinal,bound,input length,diagnostic FNV-1a64 checksum,value,owner,generation,
invocation-plus-one (zero for unsampled),entry history prefix,RET offset,
acknowledgement,start/end raw ticks,start/end AUX,and batch number. Exact input
bytes, not the diagnostic checksum, own the internal request/result join.
FLUSHED contains ID,batch number,confirmed calls,sampled calls. HISTORY contains
chunk number,absolute action prefix,kind,generation. REPORT contains generation
and row count. SAMPLE contains ID,generation,invocation,entry value,lifetime
start sequence,end-observation kind/value. IO contains the number of stdout
writes that returned EAGAIN before finalization. This is a snapshot (a lower
bound on total pressure), since writing the final rows may also encounter it.
DONE contains stop reason,arms,
actions,accepted commands,calls,sampled,unsampled,batches,flushes,detach count,
and actual worker-join count.

The controller retains the complete bounded input ledger, actual history
chunks and copied Reports until terminal verification. Every normal batch
is checked against all512 journal words, original ownership, exact counters
and request order. Reports must account for every sampled request exactly
once. Raw endpoint unavailability is preserved; it never removes a request.
These are callback-positioned raw ticks, not calibrated application time.

Input reads, output writes and channel admissions are nonblocking in the
controller. Unsent bytes and packets stay owned on backpressure. STOP and the
scheduled end stop accepting input and finish all already accepted work;
removal may cause those calls to be classified Removed. There is no in-flight
cancellation. Success requires final/empty checkpoints, worker detach, actual
join, complete history/Report joins, complete stdout writes, the unchanged
shutdown deadline, and normal process exit zero. DONE bytes alone do not
establish success if the subsequent deadline/exit receipt fails. Any failure
is process failure, never a successful cancellation or shortened population.

This finite service retains the normal profile's one-thread/depth-one scalar
leaf contract: immutable source/input/maps, sole entry, matching ordinary
CALL/RET, no signals, reentry, tail entry, unwind, fork, active CET or unload.
Code owners remain process-lived after shutdown. The older two-call native
oracle covers its own fixed cases; it does not trace this service or its4096-byte
inputs. This service adds external input and timed control. General application,
module lifetime, browser, independent accuracy and full-A5 gates remain open.

The external `session_driver.py` checks this particular reproducible 41-byte
build at ELF VA4096, with complete-file SHA256
`8a238b77d4cf32c3dcea5aa0fc2a9ec55e58dbc8dc233c7c9d4100e998bd491d`.
The fresh outer qualification authenticates the compiler/source selection;
the producer independently checks these bytes before and after the child.
Its scalar oracle requires RET34 for zero bound or a found NUL and RET40 for
nonempty bound exhaustion. Other builds require their own reviewed oracle.
The full mode submits40 calls across520 epochs, including calls beyond history
prefix512. The backpressure mode submits1024 calls and one FLUSH, withholds
stdout reads for250 ms after READY while continuing stdin writes, and requires
at least one actual EAGAIN in the IO snapshot. Both require all520 arms and521
actions. The requested-stop mode submits64 calls before STOP. Duplicate-ID
and partial-EOF modes must fail. Every producer retains one absolute15 s bound
from before spawn through normal reap and acceptance; none of these cases is
a performance or scheduling-accuracy measurement.
