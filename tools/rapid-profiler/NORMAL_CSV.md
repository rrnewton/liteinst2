# Ordinary CSV function example

`normal-csv-work` runs sixteen fixed valid CSV records through a loaded C leaf, then installs normal-caller callbacks and repeats exactly those sixteen ordinary calls. Empty input is one empty field. This example checks application results and complete SDK accounting; it does not establish general CSV syntax validation, native full-state equivalence, timing accuracy or performance.

```text
ordinary-interval normal-csv-work CANDIDATE TRUSTED_FINAL ELF_VA LENGTH
```

Build the exact [C source](normal-work/csv_fields.c) as a supported scalar shared object. Independently retain the complete trusted final ELF and derive the complete `csv_fields` ELF virtual address and extent from that final object. `ELF_VA` is not a file offset or loaded address. Candidate and trusted files must be distinct, immutable files. Run a fresh process in the existing strict environment with the external 20 CPU-second, 30 wall-second and 1 MiB output limits. The application uses one non-resetting cooperative 15-second deadline and one pinned main caller. A hung target remains the external owner's responsibility.

The explicit certified-block constructor retains the existing complete CFG, sole-entry, scalar ABI, every-RET, five-byte role-window and 256-byte bounds. It does not relax the original 80-byte whole-function constructor or manufacture patchable geometry. Every declared return must occur in this corpus; an unpatchable or unexercised role fails. The independently compiled caller must be inspected for an actual CALL, its continuation and the subsequent volatile result store. The same-thread checkpoint follows actual returned calls plus complete input, file, source and generated-image postflight. Copied stack/return-word consistency is not an independent physical-return witness; no expired return slot is reread.

The output is one 17-field numeric CSV header, sixteen ordered case rows, then a `normal-csv-work CSV_FUNCTIONAL_PASS` terminal with process, thread, CPU, generation, the private `caller_entry` address and exact accounting totals. The copied return words must separately be joined to `caller_entry` plus the CALL continuation offset observed in the same release binary. Raw tick/AUX endpoints are preserved, including valid zero intervals, without duration estimates. A terminal is successful only together with a normally closed zero-exit process and complete output validation: the final deadline check follows output. Output is bounded by 8192 bytes.

The collector requires all sixteen literal expected results in each leg, complete guarded storage, all sixteen records, the complete 512-word journal including its zero tail, all Report payloads/ranks and the exact Published/Removed history. It performs one populated checkpoint, one empty checkpoint and explicit detach. A failure aborts before live calling state and input owners unwind. Executable owners remain process-lived. Continuous no-writer/no-unmap, no reentry, signal entry, cancellation, unwind, fork or active CET obligations are unchanged; metadata and source scans do not prove them.

The CSV native full-state adapter remains a separate qualification step. Existing native and timed qualifications retain their own populations and conclusions.
