## Correctness oracle (the gate)

At every iced-x86 instruction boundary in each `.text`, the
scanner length, movable bit, and relative/RIP-relative/
interception class flags were compared with iced plus
`liteinst-jit` admission (`decode_one` class for
relative/RIP/intercept facts and `decode_supported` for
allowlisted Ordinary admission). A false movable is the
non-conservative direction and blocks the result, as does any
skipped/invalid boundary: the driver fails closed without
printing speed cells when `skipped` is nonzero. A maintained
generated-encoding cross-check in `tests/external_cases.rs`
additionally pins scanner length and movable-implies-admitted
against the same oracle over fixed prefix/REX/opcode-map
families (11,641 iced-valid generated cases in the fix-round
run), including the external HLE, REX/66, VEX/EVEX, EXTRQ,
no-ModRM, CR/DR, and VMPTRLD regression rows.

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| libc | 366,364 | 0 | **0** | **0** | 308 | 0 / 0 / 0 | 35.54% | 64.46% | 59.80% |
| libLLVM | 15,822,602 | 0 | **0** | **0** | 36 | 0 / 0 / 0 | 29.47% | 70.53% | 70.83% |

Site counts from the oracle sweep: libc 68,066 direct-relative,
11,548 RIP-relative, 512 intercept; libLLVM 2,930,545
direct-relative, 294,143 RIP-relative, 26 intercept. Missed
movable cases are conservative cost only (oracle movable,
scanner fallback), not correctness failures.

## Speed (run 1 medians)

| corpus | scanner | iced stream | supported stream | fast end-to-end | full end-to-end |
|---|---:|---:|---:|---:|---:|
| libc | 145.0 MB/s, 34.85 Minsn/s | 185.3 MB/s, 44.51 | 72.8 MB/s, 17.48 | 82.5 MB/s, 19.82 | 32.9 MB/s, 7.90 |
| libLLVM | 144.5 MB/s, 36.54 Minsn/s | 200.6 MB/s, 50.71 | 70.0 MB/s, 17.70 | 90.8 MB/s, 22.95 | 32.9 MB/s, 8.33 |

These are the post-review-fix numbers (effective REX/66
prefix state, transactional exclusion, completed map tables).
Run 2 medians agree in shape: scanner 142.7 / 146.4 MB/s, iced
185.4 / 200.2 MB/s, supported stream 72.7 / 69.8 MB/s, fast
end-to-end 81.6 / 91.5 MB/s, full end-to-end 33.8 / 32.7 MB/s.

Reading: after the correctness fixes, scanner-only throughput
is below same-run iced decode-only (0.78× on libc, 0.72× on
libLLVM) — the scanner is not a faster raw decoder. The
measured gain remains end-to-end: copying scanner-movable
runs with memcpy and full-decoding only the rest is 1.13×
(libc) and 1.30× (libLLVM) the sequential S3-A
supported-decoder stream, and 2.51× / 2.76× the one-shot
full-decode-and-copy baseline in this driver. The fast path
therefore leaves roughly 60–71% of real `.text` bytes in
movable runs untouched by full decode, under the
known-boundaries constraint above.
