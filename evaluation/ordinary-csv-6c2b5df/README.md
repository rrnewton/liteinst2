# Ordinary CSV application: functional qualification

At `6c2b5df4e70d0dc538709fb21fb3a1111fa9ddc7`, one release qualification
passed all 16 original and 16 instrumented calls to the compiled 126-byte CSV
field counter. Every literal result matched (33 fields per leg), including
quoted fields, doubled quotes, empty records and both original RET paths.

The ordinary Rust caller emitted a real indirect CALL followed immediately by
a volatile result store. Its complete 20-byte extent was inspected; every
recorded return word matched the actual caller's continuation at offset 15.
The run checked guarded input/results, complete source and generated bytes,
exact private-source/shared-image mapping classes, all 512 journal words,
16 retained records, two publication-history actions, 15 next-entry return
confirmations and the final same-thread checkpoint. The child exited normally
with ECHILD, empty stderr, unchanged inputs and no rescued descendants.

This is functional application evidence. Full architectural-state comparison
of the CSV body uses the separate native oracle; this result does not establish
full state preservation for the Rust caller, throughput, timing accuracy,
arbitrary CSV compatibility or completion of A5. Raw TSC endpoints are retained
in `results.csv` without interpreting them as a performance measurement.
