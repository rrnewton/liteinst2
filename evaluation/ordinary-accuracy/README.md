This experiment uses the existing literal 37-byte `exact_work_nonempty` leaf
to compare retained intervals with the complete invocation population.
`truth.py` prepares inputs and independent algebraic results before execution.
It does not run the application or award an accuracy result.

For one trial:

```
python3 -B evaluation/ordinary-accuracy/truth.py \
  --master 16b3b34b02c2f1054381195ee3d0767b493b427ad041bbfd8924e630d0f369b1 \
  --phase comparison --trial 1 --workload late_expensive \
  --output ignored/accuracy/comparison-001-late
```

The output contains all 2,048 input rows, a selected-session result table,
per-invocation original work counts and a manifest binding their exact bytes.
An existing output directory refuses. The input grammar is one nonempty
unquoted printable CSV field, 1–64 bytes. Every generated byte reaches the
leaf; no CSV unescaping changes its work. The selected function ID is 41.
The source is
[`exact_work.S`](../../tools/rapid-profiler/exact-work/exact_work.S).

Each of `calibration`, `holdout` and `comparison` has 100 separately derived
trial seeds. A counter-based SHA-256 stream with rejection sampling changes
the payloads; `varied` also changes loop lengths. Domain separation keeps
calibration, holdout, comparison, payload, length and initial-phase streams
separate. Reproducible random streams do not establish independence of hardware
noise or validate confidence-interval coverage.

The six workloads retain their full populations:

| Workload | Original input lengths in call order |
| --- | --- |
| `short` | 2,048 length-1 calls |
| `long` | 2,048 length-64 calls |
| `alternating` | 1, 64, repeated 1,024 times |
| `late_expensive` | 1,024 length-1 calls, then 1,024 length-64 calls |
| `blocks` | 64 length-1 calls, then 64 length-64 calls, repeated 16 times |
| `varied` | 2,048 independently drawn lengths in 1–64 |

For length n, original work is 6n+5 instructions, n conditional branches,
n−1 taken branches, n one-byte input reads and one eight-byte RET read. These
counts include the subject RET and exclude its caller, hooks and counter
readers. The existing independent interpreter and native architectural-state
checks remain necessary execution evidence. An empty input violates this
function's contract. `blocks` specifies order, not a claim that a burst fits
inside an epoch.

The manifest enumerates K={1,10,100,1000} × epoch={1,10,100} ms ×
{random,locked} initial phase. A phase offset is a requested delay relative to
the controller's first epoch. Only actual execution timestamps can establish
its realization; input generation cannot do so. The randomized offset is
paired across K at a given cadence. No process is retried by this generator.

Two opt-in execution profiles record timing on the controller's shared
`Instant` clock. `normal-selected-accuracy-phase-session` records the first
release against the original requested delay. The separate
`normal-selected-accuracy-prepared-phase-session` prepares the first accepted
input and its guarded return storage before starting that clock. Its fixed
target is epoch index 1 plus the original delay; it waits for the actual second
accepted arm before admitting the call. Later CSV polling resumes after that
call returns. This removes first-input preparation from the epoch interval.

The prepared profile adds `PREPARED_PHASE`, `PREPARED`, `TARGET_ARM` and `GATE`
observations to the existing release and per-call timing rows. Its reader
joins the target arm to the actual history publication, requires all 2,048
calls, and retains both absolute error against the original delay and lateness
against the fixed target, including whole missed periods. The original 2 ms
arm deadline, session end and shutdown fence remain unchanged. Cancellation
before invocation is a failed, incomplete population after real cleanup;
it cannot produce `DONE` or a successful accuracy result.

The public owner exposes `prepared-phase-prepare` and
`prepared-phase-functional` through
[`accuracy_functional_owner.py`](../ordinary-selected-session/accuracy_functional_owner.py).
Both observation profiles leave phase realization and hardware accuracy
unresolved. A pre-call clock sample cannot bound subsequent scheduler delay.
Earlier phase results and the full experiment denominator remain separate.

These leaf workloads are one part of A5. Straight-line, nested, recursive,
multiple/tail-return, crossing-epoch and cache-model workloads still require
their own ground truth and execution profiles. Hardware counter errors and
minimum resolvable intervals/events require separate calibration before any
comparison. Native/reference, always-on, back-off and perf must run separately
on identical inputs. Their interval error, population bias, coverage and
observer perturbation remain separate results; unsampled calls stay in the
population denominator.
