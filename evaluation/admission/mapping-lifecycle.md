# Original anonymous mapping lifecycle

This slice connects original singleton Linux x86-64 mapping syscalls to the
admission source catalog. It is a finite validation target for claims 1, 2 and
4. It does not establish the complete B3 ordinary-application milestone, later
exec support, writable aliases, general instruction-head discovery or B4
artifact validation. No performance result is claimed here.

The independent native oracle constructs a static ELF controller and a private
anonymous page. The program itself performs five original mapping calls:
`mmap(RW)`, `mprotect(RX)`, `mprotect(RW)`, `mprotect(RX)`, and `munmap`.
Between them it copies two different source versions from nonexecutable data
and executes one original `cpuid` in each version. The second selected PC
moves within the same mapping incarnation. Production source acquisition uses
owner-captured bytes and a heads-only resolver; fixture literals remain in
test code.

The owner temporarily restores the application's logical executable
permissions during exactly one original mapping syscall, under a singleton
hold. This restores the old r/w/x inputs observed by `mprotect` permission and
protection-key decisions. It does not certify hidden VMA flags or arbitrary
stateful security-module history. Actual ENTRY, EXIT, complete
map tables and full state precede interpretation. The owner then closes all
current application executable pages before invoking the source resolver.
Only a consuming native quarantine proof permits one generation transition
and installation of a fresh immutable source catalog leaf. Historical leaves,
plans and CALL-return obligations remain retained after rewrite or unmap.

The mapping profile accepts isolated complete private anonymous VMAs, RW/RX
transitions, whole unmap, and a positively observed native personality without
`READ_IMPLIES_EXEC`. Continuations, stack/TLS addresses and saved CALL source
and return intervals may not intersect the affected range. Unsupported or
partially changed mappings close the transaction; errno alone never establishes
that the map set stayed unchanged. Signals, thread creation and later exec
remain outside this profile. Complete legal entry heads are still an unsafe
caller obligation.

Five named native cases cover the complete trajectory, a stale capture reply,
resolver panic, resolver expiry at the original absolute deadline, and
independent comparator corruption. The raw tracer uses its own ptrace control,
register and XSTATE reads, map parser and literal expected effects. It compares
all GPRs, complete exported XSTATE, signal masks, fixed stack/data, original and
armed code bytes, and exact owned mapping descriptors. ASLR mappings and the
private control island retain exact per-lane descriptors. The archived vDSO
has one explicit permission transition: its independently observed original RX
role is restored for the logical window and actual ENTRY/EXIT, while the
before-window and quarantine captures require NX. Every other vDSO descriptor
and raw-line byte remains exact; wrong-phase permissions and changed identity
are corruption controls. No map row is omitted and there is no cross-process
address normalization. Cleanup is established by
pidfd readiness and an actual no-child result, separately from logical closure.

The persistent kernel journal owns five immutable map-capture slots, including
raw-wait observations before semantic ENTRY/EXIT classification. Failed and
unwound prefixes have distinct typed outcomes and survive admission-owner
teardown through the diagnostic reader. Raw map text is process-local evidence
and is never exported into evaluation receipts.

Reservations retain the 64 MiB lifetime cap and never refund unused capacity.
Only a validated operation that can add executable source reserves byte-dense
new heads/candidates; other mapping operations reserve a complete unchanged or
smaller source set. A successful maximum-sized native XSTATE query certifies
its fixed exported extent for this held incarnation. Every retained observed
state must match that extent and identity; raw journal buffers remain 64 KiB.
This is evidence-size accounting, not an RSS measurement or relaxed state
comparison.

Run the unchanged six-command protocol from a clean committed checkout:

```sh
python3 evaluation/admission/run.py --expect-revision "$(git rev-parse HEAD)"
```

The JSON receipt records the exact source revision and source census, hardware,
commands, all harness totals, named fixture outcomes and physical cleanup. The
new native namespace is `test/b3_mapping_admission`; its five exact test names
are listed in `corpus.json`. A source proposal or a partial failed receipt is
not a qualified result. A subsequent result report links the actual receipt.
