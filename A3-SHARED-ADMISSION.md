# One rewrite core and pre-admitted offline pages

Design outline at source revision `03ed2c313c66274b623517f788f03ad43b13e752`.
This is a proposed contract, not an implemented exemption or a performance result.
The offline and runtime paths must share instruction facts, CFG construction,
patch planning and encoding. Their adapters acquire bytes and publish results in
different environments; they must not reimplement those algorithms.

First implementation work is consolidation, before adding another offline or
runtime analysis path. A wrapper around duplicated matches is insufficient: move
the actual classification and graph algorithms, migrate consumers, and remove the
old implementations. The freestanding decoder's no-allocation/signal constraints
must survive; making it depend on the std publication runtime is not acceptable.
No all-start scan may be replaced by a linear walk merely to share code.

The E9Patch comparison frontend/RPC ordering remains an external reference and
transport adapter. Sharing LiteInst algorithms does not mean rewriting that
independent reference to agree with LiteInst.

## Current inventory and implementation boundary

Source audit at `fd50d5ef02fd042fa4282cb83224d1b60900723c` confirms the
consolidation above. Offline imports and runtime admission use
`liteinst-x86` instruction facts; bounded graph consumers use
`control_flow::{build, collect_block_cuts}` and its indexed traversals.
Offline singleton/grouped requests and live selected publication use the same
core planner, fitting and encoder. `trampoline::observer_sequence` now owns the
common save/callback/restore sequence. ELF serialization, remote writes and
in-process publication remain separate ownership and output adapters.

The two concrete fact/policy duplications identified by that audit are merged:

1. The freestanding page decoder's `mov_guard`, `add_guard` and `region` use
   `liteinst-x86::gpr` and the shared decoder factory. Each adapter retains its
   exact width filter, the region's AL/span's CL exceptions, independent
   re-decodes and identity checks.
2. `quiescent::whole_function` and the rapid profiler's ordinary CFG adapter
   use `scalar_profile::read_only_caller_saved`. Their entry/backedge, size and
   qualification checks remain distinct; the shared predicate preserves the
   original register aliases and immediate classes.

[Current-source validation](evaluation/shared-x86/freestanding-facts/README.md)
records 15 finite decoder/descriptor/model subjects and 138 reader controls.
[Workspace validation](evaluation/direct-program/ledger-chunks-validation/README.md)
retains the complete test census and earlier failed attempts. These fact merges
do not establish complete CFG recovery or resolve corpus placement failures.
All-start scanning and each consumer's instruction policy remain unchanged.

The initial live certificate implementation should use a separately named fixed
ET_EXEC/zero-bias subset with no unresolved code relocations. It must still meet
every completeness and mutation condition below. The proposed type transition is
an inert parsed certificate, verified coverage, a load-bound dependency group,
then an owner-only pre-admitted group. `liteinst-artifact::Metadata` and
`OracleChain` cannot mint the final state. Reuse admission's `Snapshot`,
`LegalEntrySet` and `core_bridge::export` for descriptive facts; bind actual mapped
bytes through the launch owner's held-source acquisition and mapping/admission
generations. The owner's maintained domain and dependency index must revoke the
whole group before any relevant effect. Whole-domain revocation is an acceptable
first implementation; selective revocation needs its own proof. All certificate,
index and history allocations remain bounded before publication.

Up-front authentication is stricter than the study's lazy first-use cache: no
eligible page enters the admission fault gate, including before constructors or
IFUNC execution. Load-time validation is measured separately. Unchanged eligible
pages must have zero admission faults, decoder/CFG starts, replans, admission maps
refreshes and per-entry certificate lookups. These states and the live exemption
remain unimplemented; current caller-supplied completeness declarations do not
qualify.

The historical 2,053-site candidate exceeded Linux's program-header limit.
The packed RX-run writer addresses that loader constraint, retains exact owned mappings, checks the
1,170-header ELF64 bound, and is already used by the grouped path. Later evidence
records 661 headers and original/LI2 `--help` parity; that finite case does not
establish general program coverage. The broader jump/PUSH/POP upstream corpus
still fails: cat/head withhold all output after 88/80 core refusals, and wc reaches
the unchanged 64 MiB ledger limit with unknown planning counts. All 27 native rows
are retained: 18 original/E9 passes and nine LI2 unobserved. The separate jump-only
cat/head/wc corpus passed all 27 rows. See the existing
[upstream result](evaluation/direct-program/grouped-upstream-result/README.md)
and [jump-only result](evaluation/direct-program/corpus-result/README.md).

## Page certificate

A new versioned, producer-authenticated coverage record is required. Existing
`liteinst-artifact::Metadata` authenticates declared sites and content but
intentionally grants no clean-page verdict. Existing `OracleChain` is an in-memory
exact-snapshot cache, not a persistent offline admission certificate. Neither
becomes execution authority through a new label.

The record binds:

- Original object identity: optional build-id as a lookup key, exact source digest,
  segment/file offsets, byte lengths and page geometry. Build-id alone is not byte
  identity. Preserve a separate patched artifact identity.
- Compatibility: scanner/CFG/planner/encoder versions, selected-instruction policy,
  hook ABI, CPU/XSTATE/CET requirements, relocation/load-bias schema and arena
  layout. Any mismatch is a miss, never a partially accepted certificate.
- For each eligible executable page: original and final SHA-256 page hashes,
  complete byte classification, instruction/entry facts, selected sites and their
  completed patch plans. Include page-tail zeros and all bytes the CPU can fetch,
  not only section contents.
- Dependencies: instruction halos, neighboring source edits, shared generated
  pages, hooks, routing tables, relocation bindings and their exact identities.
  Cross-page dependencies are an atomic admission/invalidation group.
- Explicit noneligible pages and reasons: unscanned bytes, unresolved execution
  entries, partial patches, unqualified generated code or unsupported bindings.
  A selected-site N/N report is not a page coverage certificate.

Proof variants distinguish `CleanAbsent` (the all-start scan proves no selected
instruction can overlap the complete target page, with required halo bytes
authenticated) from `PatchedSites`
(all selected executions are transformed and their entry/resume obligations
are discharged). Existing `RuntimeScan` can prove the former without an
`AllInstructionHeads` declaration. That does not turn a partial linear ledger
into a complete CFG. Both variants require complete byte and boundary accounting;
only the latter uses entry restrictions to justify patch transformations.
For this first offline exemption, the owner's additional requirement of complete
CFG reconstruction with no gaps applies to both variants. `CleanAbsent` with
unresolved CFG remains noneligible, despite the broader existing runtime Clean
semantics. Broader offline eligibility is not selected by this proposal.

The trusted producer must establish that every possible execution entry allowed
by the runtime policy is covered. A contiguous valid linear partition does not
exclude branches into an instruction's middle or executable data. Complete CFG
facts therefore require either authenticated entry restrictions enforced by the
runtime, or coverage of alternate starts. The shared all-start scanner must
account for selected opcodes in data/overlapping decodes, including the 14-byte
boundary halo. Unknown indirect targets, returns, signals and restored contexts
cannot silently become impossible entries. If their obligations remain open,
the page remains gated. Any generated page reachable from a certified page needs
the same selected-instruction and entry-policy accounting.

## Up-front admission

The loader consumes certificates before any application thread, ELF constructor,
IFUNC resolver or signal continuation can execute the associated bytes. Loading
is phased: resolver code must itself be admitted or gated before invocation;
its result can then bind dependent pages. An unresolved page does not become
exempt merely because the loader needs to execute something:

1. Hold execution and mutation ownership. Resolve the object through a stable file
   descriptor/snapshot; authenticate the certificate's trusted provenance and
   compatibility. A checksum proves integrity, not truthful CFG facts.
2. Authenticate the original snapshot, then bind the actual load bias, relocation
   results, hook and arena addresses to derive the expected final page/dependency
   bytes and hashes. Text
   relocations or late bindings need a described deterministic transformation and
   authenticated final bytes; otherwise those pages are noneligible. Hashing the
   pre-relocation file does not validate post-relocation memory.
3. Install source overlays and all generated dependencies while no entry is
   possible, then read back and hash the actual final mapped bytes against the
   bound expected image. Establish W^X, writer/alias control, runtime CPU support
   and required instruction visibility. Retain ownership across hash, installation and RX
   publication, so there is no hash-to-execution race.
4. Bind a non-reusable mapping incarnation plus generation to the verified proof.
   Publish the dependency group into the maintained address-space view as
   `PreAdmitted`, and expose RX only after all group prerequisites are ready.
   Such pages are omitted from the page fault gate from the start.

For unchanged pre-admitted pages the required runtime counters are exactly zero:
admission faults, decoder starts, CFG reconstructions, replans and admission maps
refreshes. There is no per-entry certificate lookup. Lookup/hashing/binding at
startup is real work and must be reported separately; this design does not claim
zero startup validation, zero ordinary OS demand paging or zero hook overhead.
A stronger immutable backing identity could later replace repeated content
hashing, but build-id or timestamps alone cannot do so.

Sparse overlays preserve unchanged original pages. The loader owns every fixed
mapping; it never uses MAP_FIXED over an unrelated mapping. Clean certified pages
need no overlay. Unscanned pages and newly introduced code use the same runtime
analysis/planning path while gated. A dlopen object may itself carry a valid
certificate, but its new mapping still needs up-front authentication before its
constructors run; it never inherits authority from a previous mapping at that VA.

## Invalidation and concurrency

The maintained address-space view is the authority; repeated full `/proc/maps`
reads are not the invalidation protocol. The runtime must mediate every relevant
mutation before it becomes visible, across all threads. Updating metadata after
a successful syscall is too late if another thread can execute in between.

| Trigger | Required transition before exposure |
| --- | --- |
| `mprotect`/`pkey_mprotect` changes on certified pages | Revoke the affected proof/generation and dependent group before effective protection changes. Adding write access requires exclusion/drain and NX; restoring execute requires authenticated readmission. Permission-only calls may use an explicitly proven unchanged fast path, not an implicit exemption. |
| `mmap`/`MAP_FIXED`, `munmap`, `mremap`, exec, loader replacement | Retire affected mapping incarnations, revoke dependency groups, and assign fresh identities before replacement ranges can execute. Reusing the address, inode or build-id does not preserve authority. |
| Writes, writable aliases, COW changes, JIT or text relocations | Gate/drain affected code and all dependent aliases first, advance the content generation, then allow mutation. Unknown external writers or unmediated aliases disqualify up-front exemption. A private file mapping alone does not prove immutable backing. |
| Hash, certificate, policy or dependency mismatch | Keep NX, invalidate the whole affected dependency group and invoke runtime fallback or refuse explicitly. Never execute first and repair later. |
| Shared trampoline/hook/router retirement | Revoke all incoming certified groups and drain live/saved execution contexts before unmapping or reusing generated storage. |

A direct store cannot reliably be noticed by an eventual maps refresh. Either
writes are impossible under enforced ownership or their first attempt traps into
the mutation protocol. File-backed aliases, another process modifying a backing
file, `/proc/*/mem`, ptrace and similar authorities need exclusion/enforcement or
an explicit unsupported threat model. RX on one alias does not protect another.
This is an exact precondition, not a claim that the current runtime already
mediates all such mutations. Fork can retain certificates only with verified
inherited immutable bytes and per-process ownership/generation bookkeeping; exec
always creates a fresh namespace.

## Joint boundary and validation gates

Li2core owns shared facts/CFG/plans/encoding and the versioned offline coverage
record. The admission layer owns pre-entry binding, mapping generations, mutation mediation,
gate exclusion, invalidation and dependent-runtime lifetimes. The consumer should
accept a verified, load-bound page group, not a caller boolean named “scanned”.
A parsed certificate is inert; only the actual execution owner can mint a live
admission record. The runtime fallback remains available for every cache miss.

Required paired controls use the same programs and selected policy with the
cache disabled/enabled. They compare application output and state, selected-site
coverage and patch plans; pre-admitted execution must report zero admission
faults/scans and no page being temporarily fault-gated. Negative cases cover
same-build-id changed bytes, wrong page hash, malformed/untrusted certificate,
policy/CPU mismatch, nonzero load bias, text relocation, partial page/gap,
cross-page instruction, embedded opcode, indirect entry, concurrent mprotect,
MAP_FIXED address reuse, writable alias, stale reply and dependency retirement.
Refused certificate cases must invoke the unchanged runtime fallback or refuse
while still gated; a runtime scan refusal remains a refusal. Existing publication
lifetime, code-as-data, ABI and saved-context contracts remain mandatory. A multithreaded
mutation test must show no uninstrumented entry before revocation completes.

Existing real-program observations remain separate from this proposed feature:
`evaluation/overlapping-neighbor-corpus/` records the 2,053-site LI2 artifact
matching original `e9patch --help`; the earlier ENOEXEC remains in
`evaluation/full-program-entry-veneer/`. `evaluation/functional-corpus/` retains
1,035 missed input/action pairs and no generated-product execution in that
campaign. The subsequent `evaluation/functional-selfhost/` did execute generated
frontends/backends, but its stock extension remains 21 accepted, one failed and
two unobserved comparisons. None proves complete real-program execution coverage.
Next executable acceptance must exercise the generated products on real inputs,
retain every original refusal and compare outputs against the original program;
`--help`, valid ELF serialization and N/N planning are insufficient by themselves.
